\mkmexecsummary

PhysicalRisk is a flood risk assessment and Physical Risk Swap (PRS) pricing
platform developed by MKM Research Labs. The platform generates synthetic
portfolios of flood gauges, residential properties, and mortgages within a
river catchment, then simulates storm events to compute property-level flood
hazard curves, risk-adjusted mortgage valuations, and PRS contract pricing.

\subsection{Capabilities}

\begin{itemize}[nosep]
    \item \textbf{Synthetic portfolio generation} --- configurable portfolios of
          gauges, properties, mortgages, storms, and counterparties.
    \item \textbf{Flood simulation} --- storm-to-gauge response modelling with
          nearest-gauge flood propagation to property level via synthetic gauges on the
          river centreline (v2.1).
    \item \textbf{Hazard curve construction} --- GEV-fitted exceedance
          probabilities at gauge and property level.
    \item \textbf{PRS pricing} --- CDS-equivalent quarterly pricing of Physical
          Risk Swaps with five-component basis waterfall analysis.
    \item \textbf{Mortgage pricing} --- risk-adjusted mortgage valuation with
          affordability, LTV, and flood risk credit spread adjustments.
    \item \textbf{Interactive visualisation} --- Folium-based map with tabbed
          analysis panels, context menus, flood animation, and PDF report
          generation.
    \item \textbf{REST API} --- Flask server exposing all data and analytics
          via JSON endpoints.
    \item \textbf{PDF reporting} --- automated property, gauge, risk portfolio,
          and PRS trade confirmation reports.
\end{itemize}

\subsection{Architecture Overview}

\begin{lstlisting}[language={},caption={Platform architecture}]
phys.py (CLI)
  |-- server      --> src/server.py --> src/routes/*.py (Flask API)
  |-- port        --> src/port/src/*.py (generators)
  |                    |-- src/port/cdm/*.py (schemas)
  |                    |-- src/port/rand/thames/*.py (random modules)
  |                    |-- src/models/*.py (analytical models)
  |-- visual      --> src/visual/ (Folium map + interactivity)
  |-- check       --> dependency verification
  |-- config      --> configuration display

config.py         --> PortfolioConfig (singleton, paths, catchment)
data/
  |-- input/thames/   (generated portfolios + timeseries)
  |-- output/         (PDF reports, PRS trades)
  |-- results/        (interactive visualisation HTML)
\end{lstlisting}

\section{Installation and Setup}

\subsection{Prerequisites}

\begin{itemize}[nosep]
    \item Python 3.13 or later
    \item GDAL system library (for geospatial operations)
    \item QuantLib (optional, for CDS pricing --- analytical fallback available)
    \item Node.js and npm (optional, for JavaScript tests)
    \item \LaTeX{} distribution (optional, for building documentation PDFs)
\end{itemize}

\subsection{Installation}

\begin{lstlisting}[language=bash,caption={Installation steps}]
# Clone repository
git clone <repository-url> PhysicalRisk
cd PhysicalRisk

# Install Python dependencies
pip install -r requirements.txt

# Verify installation
python phys.py check

\texttt{flask\_cors}, \texttt{folium}, \texttt{pandas}, \texttt{numpy},

\texttt{rasterio}, \texttt{geopy}, \texttt{shapely}, \texttt{matplotlib},
\texttt{seaborn}. Each is reported as \texttt{OK} or \texttt{MISSING}.

\subsection{Catchment System}

Each catchment defines its geographic region in \texttt{data/catch/<id>.py},
inheriting from \texttt{BaseCatchment}:

\begin{itemize}[nosep]
    \item \texttt{CATCHMENT\_ID} --- unique identifier (e.g.\ \texttt{thames})
    \item \texttt{GAUGE\_POINTS} --- list of \texttt{(lat, lon, elevation\_m)} tuples
    \item \texttt{AREAS} --- region/borough names for labelling
    \item \texttt{CENTER\_LAT}, \texttt{CENTER\_LON} --- map centre coordinates
    \item \texttt{generate\_synchronized\_locations(count)} --- produce property
          locations consistent with catchment geography
\end{itemize}

The Thames catchment defines 40 gauge points along the river from Richmond to
Tilbury (elevations 4--11m) across 30 London boroughs. Additional catchments
(Rhine, Mississippi, Danube, etc.) are defined but not yet populated with
random modules.

\section{Data Pipeline}
\label{sec:pipeline}

\subsection{Generation Sequence}

Segments must be generated in dependency order. Each segment reads from the
output of earlier segments:

\begin{lstlisting}[language={},caption={Data pipeline dependency chain}]
gauges --> properties --> mortgages
             |
gauges --> gaugets --> storms --> gaugehd --> hazard
             |                                |
             +----------> propertyts -------> propertyhc
                                                |
                          counterparties --------+
\end{lstlisting}

Running \texttt{python phys.py port -{}-all} executes all segments in the
correct order. When regenerating specific segments, ensure upstream
dependencies exist.

\subsection{Data Backup}

Before generating new data, the existing input directory is automatically
backed up to \texttt{audit/<catchment>\_YYYYMMDD\_HHMMSS/}. This preserves an
audit trail of all data changes. Use \texttt{-{}-no-backup} to skip.

\subsection{Segment Details}

\subsubsection{Gauges}

Generates flood gauge stations with location, elevation, and flood stage
thresholds (Alert, Warning, Severe). Uses catchment-defined gauge points.
Each gauge includes sensor metadata (type, owner, installation date) and
historical statistics.

\textbf{Output:} \texttt{gauge.json} containing \texttt{flood\_gauges[]}
array.

\subsubsection{Properties}

Generates residential properties with location, construction details, and
multi-factor valuation. Property value is computed as:

\begin{equation*}
V = \text{area} \times \frac{\text{price}}{\text{sqm}} \times f_{\text{location}} \times f_{\text{age}} \times f_{\text{condition}} \times f_{\text{flood}} \times f_{\text{EPC}} \times f_{\text{proximity}}
\end{equation*}

The critical \texttt{FloorLevelMeters} field determines whether a property
floods --- only water above this threshold (relative to ground elevation)
counts as internal flooding.

\textbf{Output:} \texttt{property.json} containing \texttt{properties[]}
array.

\subsubsection{Mortgages}

Generates mortgage instruments linked to properties by \texttt{PropertyID}.
Includes loan principal, interest rate, term, borrower income, and computes
affordability ratio and LTV. Each mortgage carries a
\texttt{FloodRiskCategory} (Very Low through Very High).

\textbf{Output:} \texttt{mortgage.json} containing \texttt{mortgages[]} array.

\subsubsection{Gauge Time Series (gaugets)}

Simulates 60-hour flood events for each gauge. Produces hourly water level
readings showing baseline, storm rise, peak, and recession. Also generates
storm response records linking storms to gauge-level peak levels.

\textbf{Output:} \texttt{gaugets/GAUGE-xxx.json} per gauge, containing
\texttt{flood\_simulation} (hourly readings) and \texttt{storm\_responses}.

\subsubsection{Storms}

Generates storm scenarios using a Hybrid Normal-Pareto intensity distribution.
Most storms are benign; rare events cause significant gauge responses. Each
storm has spatial extent, track, duration, and intensity parameters.

\textbf{Output:} \texttt{storms.json} containing \texttt{storms[]} array
(default 10,000 events, $\sim$6~MB).

\subsubsection{Gauge Historical Data (gaugehd)}

Generates daily water level records spanning the configured number of years
(default 50). Computes percentiles (p5--p99), annual maxima, and flood
exceedance counts. Can also parse NRFA GDF CSV format.

\textbf{Output:} \texttt{gaugehd/GAUGE-xxx.json} per gauge, containing
\texttt{daily\_observations[]} and \texttt{statistics}.

\subsubsection{Hazard Curves}

Reads storms and gauge time series, simulates storm-to-gauge responses,
extracts peak levels, and fits a GEV (Generalised Extreme Value) distribution.
Computes exceedance probabilities at return periods (1, 5, 10, 25, 50, 100
years) and prices gauge-level PRS contracts.

\textbf{Output:} \texttt{gaugehc.json} containing per-gauge GEV parameters,
hazard curve points, return period levels, and PRS term structures.

\subsubsection{Property Time Series (propertyts)}

For each property, identifies the three nearest gauges (1 synthetic + 2 real)
and takes the flood WSE from the nearest gauge only (v2.1). Applies elevation
differentials and floor level thresholds. Near-field properties ($d < 2$\,km)
use retention = 1.0. Uses Manning's equation for travel time. Computes damage
ratio via depth-damage curve.

\textbf{Output:} \texttt{propertyts/PROP-xxx.json} per property, containing
\texttt{flood\_events[]} with depth, damage ratio, arrival time, and hourly
readings. Also \texttt{portfolio\_flood\_summary.json} with aggregate
statistics.

\subsubsection{Property Hazard Curves (propertyhc)}

Fits GEV to property flood depths (requires $\geq 3$ events). Computes
exceedance probabilities at three depth thresholds ($>$0m, $>$0.5m, $>$1.0m).
Prices property-level PRS via analytical CDS model. Computes five-component
basis waterfall (distance, elevation, terrain, composition, model uncertainty).

\textbf{Output:} \texttt{propertyhc.json} containing per-property GEV
parameters, hazard curves, PRS spreads, and basis analysis.

\subsubsection{Counterparties}

Generates synthetic counterparty entities (banks, insurers, reinsurers) with
credit ratings, exposure limits, and collateral requirements. Used for PRS
trade management.

\textbf{Output:} \texttt{counterparty.json}.

All entities follow standardised schemas defined in \texttt{src/port/cdm/}:

\section{Interactive Visualisation}

\subsection{Map Generation}

\begin{lstlisting}[language=bash]
python phys.py visual
\end{lstlisting}

Generates an interactive Folium HTML map with all portfolio data overlaid.
The map includes tile layer controls, measurement tools, fullscreen toggle,
and a scale indicator.

\subsection{Map Layers}

\subsubsection{Gauge Layer}

Gauge markers use water-droplet icons colour-coded by operational status
(green = operational, orange = maintenance, red = offline). Tooltips show
gauge ID and flood frequency. Click popups display equipment details, sensor
data, flood thresholds (alert/warning/severe levels), and historical context.
A RAG indicator shows flood frequency risk.

\subsubsection{Property Layer}

Property markers use home icons colour-coded by flood frequency from simulated
storms (red = high, orange = medium, green = low). Mortgaged properties show
a bank icon variant. Click popups display property details, elevation and flood
zone information, and mortgage details where applicable.

\subsubsection{Mortgage Layer}

Optional overlay showing translucent circles around mortgaged properties.
Circle size correlates with loan amount; colour indicates flood risk level.
High-leverage properties (LTV $> 80\%$) show a filled indicator.

\subsection{Context Menus}

Right-clicking a marker opens a context menu with actions:

\subsection{Interactive Panels}

\subsubsection{Property Storm Analysis}
\label{sec:prop_storm}

Four-tab panel (780$\times$560px) loaded from

    \item \textbf{Mortgage Impact} --- stacked bar chart showing retained

          negative equity count.

Three-tab panel (780$\times$560px) loaded from

\begin{enumerate}[nosep]

    \item \textbf{Flood Timeline} --- water level hydrograph with flood stage
          thresholds (alert, warning, severe).
    \item \textbf{Worst Storms} --- top 20 storms by peak level.
\end{enumerate}

\subsubsection{Property Hazard Curve and PRS Pricing}

Four-tab panel (1100$\times$750px) loaded from
\texttt{/api/v1/properties/\{id\}/hazard}:

\begin{enumerate}[nosep]
    \item \textbf{Hazard Curve} --- log-log exceedance curve with 1-in-10,
          1-in-50, 1-in-100 year flood markers.
    \item \textbf{Term Structure} --- annual flood probability over 1--30 years.
    \item \textbf{PRS Pricing} --- six-component pricing breakdown with basis
          waterfall. Shows base rate, depth threshold components ($>$0m,
          $>$0.5m, $>$1.0m), and contingent pricing.
    \item \textbf{Basis Analysis} --- gauge spread vs property spread
          comparison. Basis = gauge spread $-$ property spread (positive =
          gauge more expensive, expected).
\end{enumerate}

\subsubsection{Gauge Hazard Curve}

Five-tab panel (1100$\times$750px) loaded from
\texttt{/api/v1/gauges/\{id\}/hazard}:

\begin{enumerate}[nosep]
    \item \textbf{Hazard Curve} --- exceedance probabilities for gauge.
    \item \textbf{Annual Exceedance} --- annual probability by depth.
    \item \textbf{Return Period} --- return period curves (1-in-$X$ years).
    \item \textbf{PRS Pricing} --- QuantLib CDS pricing for gauge-level PRS.
    \item \textbf{Flood Probability} --- probability at different thresholds.
\end{enumerate}

\subsubsection{Gauge Historical Data}

Single-chart panel (700$\times$500px) showing historical daily water levels
with flood stage thresholds as horizontal reference lines. Loaded from
\texttt{/api/v1/gauges/\{id\}/history}.

\subsubsection{Flood Animation}

60-frame animation panel (860$\times$620px) showing storm progression.
Loaded from \texttt{/api/v1/propertyts/animate/\{storm\_id\}}.

\begin{itemize}[nosep]
    \item Storm selector dropdown for all available storms.
    \item Play/Pause controls with speed adjustment (1x/2x/5x).
    \item Scrubber bar to jump to any hour.
    \item Gauge markers change colour by water level (green $\to$ red).
    \item Expanding translucent circles from flooded gauges.
    \item Property markers appear when flood front arrives.
    \item Stats bar updates per frame: hour, gauges flooded, properties flooded.
\end{itemize}

\subsubsection{Mortgage Detail Panel}

Single-section panel (600$\times$520px) loaded from
\texttt{/api/v1/properties/\{id\}/mortgage}. Displays five sections: Loan
Summary, Financial Terms, Current Status, Borrower, and Risk Assessment.

\subsubsection{PDF Report Viewers}

Embedded iframe panels (850px wide, 90\% viewport height) for viewing
generated PDF reports. Include download and print buttons.

\subsection{Notification System}

Toast-style notifications provide user feedback for all actions:

\begin{itemize}[nosep]
    \item \textbf{Info} (blue) --- general information
    \item \textbf{Success} (green) --- operation completed
    \item \textbf{Warning} (orange) --- caution
    \item \textbf{Error} (red) --- operation failed
    \item \textbf{Loading} (grey) --- operation in progress
\end{itemize}

Auto-dismiss after 5 seconds. Maximum 5 visible simultaneously. Configurable
position (default: top-right).

\subsection{Backend Communication}

Frontend panels communicate with the Flask API via the
\texttt{window.\_\_BACKEND\_CONFIG} object, which stores the server URL and
endpoint mappings. The backend handler (\texttt{src/static/js/backend-handler.js})
manages fetch requests with CORS support and 30-second timeout.

\section{Docker Deployment}

\subsection{Container Image}

The \texttt{Dockerfile} builds a production image based on
\texttt{python:3.13-slim} with GDAL system libraries:

\begin{lstlisting}[language=bash,caption={Docker build and run}]
# Build image
docker build -t physicalrisk .

# Run container
docker run -p 5001:5001 -v ./data:/app/data physicalrisk
\end{lstlisting}

The container exposes port 5001 and runs
\texttt{python phys.py server -{}-host 0.0.0.0 -{}-port 5001}.

\subsection{Docker Compose}

\begin{lstlisting}[language=bash,caption={Docker Compose usage}]
docker-compose up              # Start service
docker-compose up --build      # Rebuild and start
docker-compose down            # Stop service
docker-compose logs -f         # Stream logs
\end{lstlisting}

Configuration:
\begin{itemize}[nosep]
    \item Port mapping: \texttt{5001:5001}
    \item Volume: \texttt{./data:/app/data} (persists data outside container)
    \item Environment: \texttt{FLASK\_ENV=production},
          \texttt{CATCHMENT\_ID=thames}
    \item Restart policy: \texttt{unless-stopped}
\end{itemize}
