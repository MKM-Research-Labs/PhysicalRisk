Chapter 21: Banking Interoperability (pp. 502-511)
================================================================

CORE THESIS
-----------
Before PRS can function as a market instrument, a fundamental technical prerequisite
must be satisfied: banking desktop applications must communicate through standardised
protocols. FDC3 (Financial Desktop Connectivity and Collaboration Consortium), governed
under FINOS, provides this infrastructure. Combined with CDM for data semantics and
TraderX as reference implementation, FDC3 creates a complete open-source stack.

The chapter documents concrete industry adoption and explicitly hands off to Chapter 22
with a specific promise about "Phase 6."

KEY ARGUMENTS
-------------
1. Application silos are the fundamental barrier
   - N applications require N(N-1)/2 bilateral integrations (125,000 for 500 apps)
   - Physical risk requires orchestrating weather, hydrology, property, mortgage,
     and credit risk systems
   - FDC3 transforms quadratic scaling to hub-and-spoke

2. FDC3 five-component architecture
   - Desktop Agent: central router maintaining application state
   - Intents: standardised verbs (ViewChart, ViewQuote, ViewAnalysis)
   - Context Data: standardised nouns with extensible schemas
   - Channels: selective context sharing (system + application channels)
   - App Directory: REST-based discovery catalogue

3. FDC3 2.2 enables browser-based deployment
   - Web Connection Protocol (WCP), Desktop Agent Communication Protocol (DACP)
   - Cloud-hosted risk analytics deliver results via FDC3

4. Industry adoption is mature
   - BlackRock Aladdin FDC3 2.0 conformant (Sept 2024)
   - Morgan Stanley: open-source ComposeUI with .NET bindings
   - BMO: 73 applications, 50% faster development cycles
   - Citi, UBS, NatWest, State Street all using FDC3

5. FDC3 + CDM = complete interoperability
   - FDC3 = how applications talk; CDM = what they exchange
   - TraderX + CDM integration demonstrated at FINOS hackathon
   - CDM generates executable libraries in Java, Python, TypeScript, C++, DAML

6. Security: signed contexts, encrypted channels for sensitive data
   - Essential for property-level risk assessments and portfolio exposure
   - Desktop Agent Bridging (FDC3 2.1) connects legacy systems

KEY MODELS AND FRAMEWORKS
--------------------------
- FDC3 standard (five specifications)
- FDC3 2.0 (transactional), 2.1 (bridging), 2.2 (browser via WCP/DACP)
- FINOS governance under Linux Foundation
- CDM with Rune DSL
- TraderX reference implementation
- NatWest BackPlane (open-source bridge)
- FIX protocol (historical precedent analogy)

CDS INFRASTRUCTURE ANALOGY
---------------------------
Reinforces at the technology layer. Same platforms (Aladdin, ComposeUI) that process CDS
now support FDC3, meaning PRS integration literally runs on the same technology stack.
FIX protocol analogy: FIX transformed trading from bilateral to standardised communication.
FDC3 aims to do the same for desktop workflows. PRS benefits without having to build it.
