Chapter 3.5: Weather - Precipitation Mapping (pp. 133-142)
================================================================

CORE THESIS
-----------
The final sub-chapter bridges the gap between atmospheric ensemble states and the
rainfall time series that hydrological and credit-risk models actually consume. Each
atmospheric scenario is translated into catchment-scale precipitation that preserves
spatial coherence (neighboring catchments share coherent storm signals), temporal
persistence (realistic storm lifecycles), and extreme-event behavior. The output is
thousands of hourly or sub-hourly rainfall time series per catchment, weighted by
Bayesian posterior probabilities from Chapter 3.4, yielding IDF curves and exceedance
probability estimates ready for flood models.

KEY MATHEMATICAL MODELS
-----------------------
1. Spatial Aggregation
   - P_catchment(t) = (1/A_C) integral_C P(x,y,t) dx dy
   - Area-weighted with sub-catchment runoff coefficients

2. Moisture Budget for Precipitation
   - P = -div(Q) + E - dW/dt (precipitation from moisture convergence)
   - P proportional to w x q (vertical motion x humidity)

3. Marginal Distributions for Precipitation
   - Zero-inflation: point mass at zero for dry conditions
   - Conditional intensity: gamma distribution with regime-dependent shape/scale
   - Extreme tails: GPD for heavy precipitation

4. Spatial Correlation
   - theta_{ij} = theta_0 exp(-d_{ij} / L_corr)
   - L_corr = 10-50 km for convective storms (localized, intense)
   - L_corr = 50-200 km for stratiform/frontal systems (widespread, moderate)

5. Orographic Enhancement
   - P_oro = P_synoptic x (1 + alpha x w_oro)
   - w_oro = v . grad(h) where h is terrain height
   - Mountains amplify rainfall on windward slopes

6. HMM for Precipitation Regimes
   - Transition matrix A_0 governing dry/light/moderate/heavy states
   - Regime-dependent occurrence probabilities and intensity distributions
   - Links to atmospheric HMM from Ch 3.3

7. IDF Products (Intensity-Duration-Frequency)
   - Maximum intensities for standard durations (1, 3, 6, 12, 24 hours)
   - Return period estimates (100-year 24-hour = 99th percentile across ensemble)
   - Parametric IDF curve fitting
   - These are the engineering-grade outputs that connect to flood thresholds

8. Scenario Families
   - Clustering thousands of ensemble members into manageable groups
   - Common impact profiles within each family
   - Probability weights from posterior distribution
   - Output: "15% probability of slow-moving convective pattern"

FORWARD REFERENCES
------------------
- Catchment-scale rainfall time series are direct inputs to hydrological models

- From hydrology -> damage functions -> expected loss -> capital -> PRS pricing
- Scenario families designed to be consumable by trading desks

CDS INFRASTRUCTURE ANALOGY
---------------------------
THIS IS WHERE THE ANALOGY WORKS BEST:

- Catchment-scale rainfall metrics with probabilities are analogous to CDS reference
  entity data
- Just as CDS requires reference entity identification (CUSIP, RED code), PRS requires
  catchment identification
- Just as CDS requires credit event definitions (bankruptcy, failure to pay), PRS
  requires flood threshold definitions
- IDF curves and exceedance probabilities are the weather-domain equivalent of
  default probabilities and loss-given-default estimates

TENSION: Contract triggers need to be objective and verifiable, but a continuously
updating distribution is inherently model-dependent. Chapter 22 must resolve whether
PRS triggers reference the model's real-time posterior probabilities OR fixed
observational thresholds (Environment Agency gauge readings). The PoC platform uses
the latter -- objective gauge readings -- which is the cleaner integration path.

CROSS-CHAPTER SYNTHESIS: Ch 3 as a whole
-----------------------------------------
What supports the CDS integration claim:
- Scenario families reduce complexity to something resembling credit rating states
  with transition probabilities
- Bayesian updating maps conceptually to mark-to-market
- IDF/exceedance outputs serve as weather-domain PD/LGD analogues
- Copula modelling is familiar to structured credit desks
- SDE ensemble generation resembles Monte Carlo VaR engines

What complicates it:
- Dimensionality vastly exceeds CDS infrastructure
- Real-time data requirements: meteorological sensor networks vs market data terminals
- EnKF requires meteorological domain expertise not found in banks
- Living distribution is a model output requiring continuous validation, unlike
  observable CDS spreads
- Infrastructure cost (compute, data feeds, geospatial systems, meteorological
  expertise) is largely non-overlapping with existing CDS infrastructure

KEY RESOLUTION: The PoC platform demonstrates that the OUTPUTS of this framework
(hazard curves, flood probabilities, PRS spreads) can be consumed by CDS-style
infrastructure. The bank does not need to run the Weather Monte Carlo itself --
it needs a service provider (or utility) that delivers the translated outputs in
CDM format. This is the same model as Markit providing CDS pricing data.
