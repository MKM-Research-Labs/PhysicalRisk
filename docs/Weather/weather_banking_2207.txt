22.7 Stress Testing Extension
================================================================

SECTION PURPOSE
---------------
Show how PRS stress testing extends the bank's existing stress framework with
storm scenarios as a new stress driver, operating at both gauge level (for the
market-maker) and portfolio level (for the mortgage book).

EXISTING STRESS INFRASTRUCTURE
-------------------------------
A bank's stress testing framework already handles:
- Scenario definition and management
- Portfolio revaluation under stressed conditions
- P&L attribution by risk factor
- Capital impact assessment
- Regulatory stress test submissions (EBA, PRA, Fed CCAR/DFAST)

PRS stress testing adds a new scenario type -- storm events -- but uses the
same infrastructure for revaluation, attribution, and reporting.

GAUGE-LEVEL STRESS (Market-Maker Perspective)
----------------------------------------------
The PoC implements per-gauge stress testing using GBM flood classifiers:

  Training:
  - GradientBoostingClassifier per gauge (40 gauges in Thames catchment)
  - 4 log-transformed features:
      log_h_s     = ln(water_level / severe_level)    [relative to threshold]
      log_t_end   = ln((hour + 1) / 168)               [storm time fraction]
      delta_log_h = delta(ln(w/s))                      [rate of rise]
      delta2_log_h = delta^2(ln(w/s))                   [acceleration]
  - Hyperparameters: n_estimators=300, max_depth=3, learning_rate=0.05,
    subsample=0.8, min_samples_leaf=50
  - Training data: 1,000 storms per gauge (260 alert-breaching + 740 sub-alert)
  - Average AUC: 0.92-0.95 across gauges

  Prediction:
  - predict(gauge_id, water_level, hour, delta_w, delta2_w) -> P(flood)
  - predict_surface(level_range, hour_range) -> 2D probability grid
  - For each (gauge, storm) pair:
      1. Synthesise hydrograph from storm parameters (168-hour horizon)
      2. Compute P(flood) at each hour from classifier
      3. CDS-in-stress valuation: cash_price = notional x P(flood) x direction
      4. stress_pnl = cash_price - current_mtm

  Output: stress P&L waterfall per position, summary statistics across scenarios

This is directly analogous to CDS spread-shock stress testing: for each
scenario, bump the hazard rate and compute the impact on the portfolio. The
difference is that "bump" comes from a physical storm scenario processed
through a GBM classifier rather than from a prescribed credit spread shift.

PORTFOLIO-LEVEL STRESS (Mortgage Book Perspective)
---------------------------------------------------
The PoC implements portfolio stress through:

  Spatial Correlation:
  - KDTree for geographic proximity computation
  - IDW (Inverse Distance Weighting) interpolation
  - Base correlation = 0.4, distance decay function
  - Properties within ~1000m share strongly correlated flood impacts

  Depth-Damage:
  - Flood depth at each property derived from gauge response and spatial model
  - Depth-damage functions map depth to damage ratio (0-1)
  - Damage ratio x property value = estimated loss

  Mortgage Impact:
  - LTV breach analysis: if property_value - damage > outstanding_balance?
  - Negative equity estimation across portfolio
  - Default probability adjustment via affordability ratio (Chapter 11)
  - Frye-Jacobs conditional LGD (Chapter 17): cLGD increases with stressed PD

  Monte Carlo Simulation:
  - 1,000 paths per scenario
  - Portfolio VaR and CVaR (Expected Shortfall) distributions
  - Sequential storm analysis: cumulative degradation from multiple events

  Claims Reporting:
  - Automated flood damage estimation per property
  - Claim report generation with loss quantification

This portfolio stress framework answers: "If Storm X hits the catchment, what
happens to the mortgage book?" -- the same question CDS portfolio stress
answers for credit events, but with spatial correlation replacing sector/
rating correlation.

STORM SCENARIO CATALOGUE
--------------------------
The PoC maintains a catalogue of historical storm scenarios:
- 260 storms that breached alert level at one or more gauges
- 740 sub-alert storms for classifier training balance
- Each storm: gauge-by-gauge water level time series over 168 hours
- Storms sourced from EA historical records and synthetic generation

This catalogue is the PRS equivalent of the credit spread shock scenarios
used in CDS stress testing. It can be extended with:
- New historical events as they occur
- Synthetic scenarios for tail exploration (Gumbel-adjusted)
- Climate-conditioned scenarios (with governance caveats from Chapter 18)

INTEGRATION WITH TRADING DESK
-------------------------------
The PoC's stress testing tab (Tab 7 of the trader workstation) shows:
- Available gauges with classifier training status
- Pre-computed storm scenarios with portfolio impact
- Custom stress scenario input and execution
- Stress P&L waterfall and summary statistics

Pre-trade: before committing a new PRS position, the trader can stress it
against the storm catalogue to assess tail risk exposure.

Daily/weekly: the full book is stressed against the scenario library to
monitor risk limits and position sizing.

WHAT THIS MEANS FOR INTEGRATION
---------------------------------
A bank extends its existing stress framework by:
1. Adding storm scenarios to the scenario library (analogous to adding new
   credit spread shocks)
2. Training GBM classifiers per gauge (one-time, periodic retraining)
3. Connecting storm scenarios to the portfolio revaluation engine
4. Adding spatial correlation to the portfolio aggregation step
5. Integrating Frye-Jacobs LGD adjustments into stressed capital calculations

The stress infrastructure itself (scenario management, revaluation, attribution,
reporting) is unchanged. Storm scenarios are a new input type, not a new system.
