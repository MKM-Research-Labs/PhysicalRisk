% ===================================================================
% 1. EXECUTIVE SUMMARY
% ===================================================================
\mkmexecsummary

This document presents the mathematical framework, calibration, and validation of the
Building Resilience Index (BRI) Model implemented in
\texttt{src/port/rand/thames/property/property\_random/resilience.py}. The model
produces two related-but-distinct outputs from a single resilience checklist:

\begin{enumerate}[nosep]
    \item \textbf{BRI letter rating} (AA / AA+ / A / A+ / B / B+ / NR) derived from a
          weakest-link aggregation across applicable hazards (Flood, Wind, Fire,
          Seismic). A \texttt{+} modifier is awarded when the operational continuity
          dimension is also met. The letter scale follows the IFC Building Resilience
          Index public methodology.
    \item \textbf{Flood resilience score} (1--100) computed per the
          \emph{BRI Resilience Function Specification} (April 2026 draft) using a
          weighted 13-measure model with regime-specific weight multipliers
          (pluvial / fluvial / coastal), four soft-cap rules, and a linear damage
          modifier $M(S, r) = 1 - \alpha_r (S-1)/99$ intended to scale an existing
          flood damage function.
\end{enumerate}

\noindent The model is designed for property-level resilience disclosure, portfolio
analytics, and (Phase 2) integration with the existing depth-damage flood loss
estimator to produce mitigation-adjusted loss-given-hazard estimates.

\textbf{Key risk:} The resilience checklist 5-level vocabulary (\emph{Not assessed} /
\emph{Partial} / \emph{Meets minimum} / \emph{Enhanced} / \emph{Verified}) drives both
the letter rating and the score. Inter-rater disagreement on level assignment would
propagate directly to both outputs. Validation should include inter-rater agreement
studies on a sample portfolio before the model enters production for assessment work.

\textbf{Calibration status:} Thames-specific. Section weights, rating thresholds, and
$\alpha$ values reflect the dominant fluvial flood hazard. Non-Thames catchments
require a separate calibration. The spec author flagged the underlying $\alpha$ and
weight values as ``first implementation, not final scientific calibration''.

% ===================================================================
% 2. MODEL PURPOSE AND SCOPE
% ===================================================================
\mkmpurpose

\subsection{Purpose}
The BRI Model provides standardised resilience assessment for individual properties.
It serves four primary functions:
\begin{itemize}[nosep]
    \item \textbf{Disclosure:} A human-readable letter grade (AA / A / B / NR) for
          reporting to lenders, insurers, and policymakers.
    \item \textbf{Portfolio analytics:} A continuous 0--1 score for aggregation,
          stratification, and tail-risk analysis across property portfolios.
    \item \textbf{Mitigation accounting:} A damage modifier $M(S, r)$ that converts
          mitigation measures into a multiplicative adjustment on baseline flood
          damage, supporting loss-given-hazard estimation.
    \item \textbf{Per-hazard transparency:} Independent sub-ratings for Flood, Wind,
          Fire, and Seismic so consumers can identify the hazard driving an
          unfavourable overall rating.
\end{itemize}

\subsection{Scope}
\begin{itemize}[nosep]
    \item \textbf{In scope:} Resilience checklist scoring; per-hazard sub-rating;
          weakest-link overall rating; ``+'' continuity modifier; flood-spec
          weighted-measure score with regime multipliers and soft caps; linear damage
          modifier.
    \item \textbf{Out of scope:} Hazard intensity estimation (covered by the Storm
          Intensity and GEV Hazard models); depth-damage curve (covered by the Flood
          Risk model --- Phase 2 integration target); insurance pricing.
    \item \textbf{Upstream dependencies:}
          \texttt{PropertyHeader.PropertyAttributes}
          (\texttt{PropertyPeriod}, \texttt{PropertyCondition});
          \texttt{PropertyHeader.Construction}
          (\texttt{FloorLevelMeters}, \texttt{BasementPresent});
          \texttt{PropertyHeader.RiskAssessment}
          (\texttt{EAFloodZone}, \texttt{FloodRiskType});
          \texttt{HistoryAndIncidents.FloodEvents.FloodDamageSeverity}.
    \item \textbf{Downstream consumers:} Governance reporting (MRC dashboards),
          property report PDFs, future integration with depth-damage flood loss
          estimator.
\end{itemize}

\subsection{Co-locating Two Methodologies}
The module deliberately hosts two related but distinct scoring paradigms.

\begin{itemize}[nosep]
    \item The \textbf{letter rating} is categorical and weakest-link-aggregated,
          mirroring IFC BRI public methodology. Its design intent is auditability and
          comparability across portfolios.
    \item The \textbf{flood score} is continuous and built for damage-modifier use,
          per the BRI Resilience Function Specification. Its design intent is to
          retain mitigation-quality detail that a letter rating loses.
\end{itemize}

\noindent Both consume the same resilience checklist input. Co-locating them avoids
duplication and keeps the calibration tables in one place.

\mkmframework

% -------------------------------------------------------------------
% 3.1 Compliance factor
% -------------------------------------------------------------------
\subsection{Compliance Factor}
Each resilience checklist field $i$ has a value in one of three forms:

\begin{itemize}[nosep]
    \item \textbf{5-level enum:} \emph{Not assessed} (0.0), \emph{Partial} (0.4),
          \emph{Meets minimum} (0.7), \emph{Enhanced} (0.9), \emph{Verified} (1.0)
          --- the dominant form across the checklist.
    \item \textbf{Strategy enum} (\texttt{BasementFloodStrategy}): four-valued enum
          with its own credit map.
    \item \textbf{Continuous} (\texttt{FloorLevelMeters}): mapped to a 0--1 compliance
          via a banded elevation table (Section~\ref{sec:flood_spec}).
\end{itemize}

\noindent The compliance factor $c_i \in [0, 1]$ is the credit assigned to field $i$.

% -------------------------------------------------------------------
% 3.2 BRI letter rating
% -------------------------------------------------------------------
\subsection{BRI Letter Rating}
\label{sec:letter_rating}

\subsubsection{Section Score}
For each of the five resilience sub-sections $S \in \{$BuildingAssessment,
SiteAndDrainage, FloodProtection, FireProtection, ContinuityMeasures$\}$ with field
weights $w_i^S$ (defaulting to 1.0; critical-control overrides up to 2.0):

\begin{equation}
    \text{score}_S = \frac{\sum_{i \in S} w_i^S c_i}{\sum_{i \in S} w_i^S}
\end{equation}

\subsubsection{Overall Weighted Score}
A diagnostic overall score is computed but is \emph{not} used to derive the letter;
the letter comes from the per-hazard weakest-link path below.

\begin{equation}
    \text{score}_{\text{overall}} = \sum_S \omega_S \cdot \text{score}_S
\end{equation}

\noindent where section weights $\omega_S$ are calibrated for Thames flood-dominant risk
(Flood 0.30, Site/Drainage 0.25, Building 0.20, Continuity 0.15, Fire 0.10).

\subsubsection{Per-Hazard Score and Rating}
For each hazard $h \in \{$Flood, Wind, Fire, Seismic$\}$, a relevance map
$F_h$ selects the resilience fields that matter for that hazard. The per-hazard score is:

\begin{equation}
    \text{score}_h = \frac{\sum_{i \in F_h} w_i c_i}{\sum_{i \in F_h} w_i}
\end{equation}

\noindent and the per-hazard letter is determined by threshold mapping
$\tau : [0,1] \to \{$AA, A, B, NR$\}$:

\[
    \tau(s) = \begin{cases}
        \text{AA} & s \geq 0.87 \\
        \text{A}  & 0.62 \leq s < 0.87 \\
        \text{B}  & 0.38 \leq s < 0.62 \\
        \text{NR} & s < 0.38
    \end{cases}
\]

\noindent A hazard with \texttt{HazardClass = None} is non-applicable and produces
\emph{N/A}, which is excluded from aggregation.

\subsubsection{Weakest-Link Overall Letter}
The overall letter is the weakest applicable letter:

\begin{equation}
    \text{rating}_{\text{overall}} = \arg\min_{h \in \text{applicable}} \tau(\text{score}_h)
\end{equation}

\subsubsection{Continuity ``+'' Modifier}
A \texttt{+} suffix is appended when the overall is not NR \emph{and} the
\texttt{ContinuityMeasures} section score meets the threshold:

\[
    \text{rating}_{\text{overall}} \leftarrow \text{rating}_{\text{overall}} + \text{"+"}
    \;\text{ iff }\;
    \text{score}_{\text{Continuity}} \geq 0.65
\]

% -------------------------------------------------------------------
% 3.3 Flood resilience score (spec)
% -------------------------------------------------------------------
\subsection{Flood Resilience Score}
\label{sec:flood_spec}

\subsubsection{Thirteen-Measure Weighted Sum}
The spec defines 13 measures with base weights summing to 100. Each measure
$m \in M$ has weight $w_m$, regime-specific multiplier $\rho_{m,r}$ depending on the
flood regime $r \in \{$pluvial, fluvial, coastal$\}$, and compliance factor $c_m
\in [0, 1]$ computed from the CDM record:

\begin{equation}
    \tilde{w}_{m,r} = w_m \cdot \rho_{m,r}
\end{equation}

\noindent The raw regime-adjusted score (0--100):

\begin{equation}
    S_{\text{raw}, r} = 100 \cdot \frac{\sum_m \tilde{w}_{m,r} c_m}{\sum_m \tilde{w}_{m,r}}
\end{equation}

\subsubsection{Banded Elevation Compliance}
For \texttt{lowest\_occupied\_floor\_elevation} the compliance is read from the
elevation margin in metres above the local water reference:

\begin{center}
\begin{tabular}{lc}
    \toprule
    \textbf{Elevation margin} & \textbf{Compliance} \\
    \midrule
    Less than 0\,m       & 0.00 \\
    0 to less than 1\,m  & 0.20 \\
    1 to less than 3\,m  & 0.50 \\
    3 to less than 5\,m  & 0.75 \\
    5 to less than 6\,m  & 0.90 \\
    6\,m or more         & 1.00 \\
    \bottomrule
\end{tabular}
\end{center}

\subsubsection{Soft Caps}
Four soft-cap rules cap the final score when critical controls fail:

\begin{itemize}[nosep]
    \item Lowest occupied floor compliance $= 0$ $\Rightarrow$ cap at 40
    \item Critical systems elevation compliance $= 0$ $\Rightarrow$ cap at 60
    \item Pluvial regime, retainage \emph{and} drainage compliance both $= 0$ $\Rightarrow$ cap at 55
    \item Fluvial/coastal regime, lower-level design \emph{and} water-resistant
          materials both $= 0$ $\Rightarrow$ cap at 65
\end{itemize}

\noindent The final score is:

\begin{equation}
    S_{\text{final}} = \max\Big(1, \min\big(S_{\text{raw}, r},\ \min_c \text{cap}_c\big)\Big)
\end{equation}

\noindent The lower bound of 1 ensures positive downstream values.

\subsubsection{Damage Modifier}
The final score maps to a damage modifier scaling baseline damage:

\begin{equation}
    M(S, r) = 1 - \alpha_r \cdot \frac{S - 1}{99}
\end{equation}

\noindent with $\alpha = \{0.65 \text{ pluvial}, 0.60 \text{ fluvial}, 0.50 \text{ coastal}\}$.
At $S = 1$ no mitigation is applied ($M = 1.0$); at $S = 100$ maximum mitigation is
$1 - \alpha_r$.

\subsubsection{Adjusted Loss}
The intended use (Phase 2 integration) is:

\begin{equation}
    \text{LGH}_{\text{adj}} = \text{BaselineDamage}(h, x) \times M(S, r)
\end{equation}

\noindent where $h$ is hazard intensity, $x$ is the existing vulnerability input set,
$S$ is the final flood resilience score, and $r$ is the flood regime.

\subsubsection{Regime Mapping}
The flood regime is derived from \texttt{PropertyHeader.RiskAssessment.FloodRiskType}:

\begin{center}
\begin{tabular}{ll}
    \toprule
    \textbf{FloodRiskType} & \textbf{Regime} \\
    \midrule
    Fluvial       & fluvial \\
    Pluvial       & pluvial \\
    GroundWater   & pluvial \\
    Coastal       & coastal \\
    Multiple      & pluvial \emph{(worst-$\alpha$ default)} \\
    \bottomrule
\end{tabular}
\end{center}

\subsection{Score Persistence}
For each property the BRI Model writes the following into
\texttt{ProtectionMeasures.RiskAssessment.GoverningBodyRatings}:

\begin{center}
\begin{tabular}{ll}
    \toprule
    \textbf{Field} & \textbf{Value} \\
    \midrule
    \texttt{BRIRating}        & weakest-of applicable hazard letters (with optional ``+'') \\
    \texttt{BRIScore}         & mean of the four per-hazard scores \\
    \texttt{BRIFloodRating}   & per-hazard letter from \S\ref{sec:letter_rating} \\
    \texttt{BRIWindRating}, \texttt{BRIFireRating}, \texttt{BRISeismicRating} & idem (or N/A) \\
    \texttt{BRIFloodScore}    & $S_{\text{final}}/100$ from \S\ref{sec:flood_spec} \\
    \texttt{BRIWindScore}, \texttt{BRIFireScore}, \texttt{BRISeismicScore} & \texttt{BRIFloodScore} $\pm 0.05$ (deterministic per PropertyID) \\
    \texttt{BRIDate}          & date of rating \\
    \texttt{BRIRatingVersion} & methodology version (e.g.\ ``BRI v1.6'') \\
    \texttt{BRIRatingAgent}   & verifier (e.g.\ ``Bureau Veritas'') \\
    \bottomrule
\end{tabular}
\end{center}

\noindent The damage modifier $M$ is returned by
\texttt{apply\_flood\_resilience\_score} but is \emph{not} persisted in the CDM
pending Phase 2 integration with the existing depth-damage model.

% 4. INPUT PARAMETERS AND CALIBRATION
% ===================================================================
\mkminputs

The model is fully table-driven. All weights, thresholds, and mappings are
externalised constants in
\texttt{src/port/rand/thames/property/property\_random/resilience.py}
(see Sections~1 and 5 of that file). The Parameter Inventory document lists every
parameter with its current value and source line; this section summarises the
design rationale.

\subsection{Calibration Provenance}
\begin{itemize}[nosep]
    \item \textbf{Section weights} ($\omega_S$): set to reflect Thames fluvial
          dominance. Flood (0.30) and Site/Drainage (0.25) take precedence; Building
          Assessment (0.20) and Continuity (0.15) follow; Fire is deprioritised (0.10).
          Sum to 1.0 (validated by \texttt{validate\_weights()}).
    \item \textbf{Rating thresholds} ($\tau$): calibrated against the Thames synthetic
          property generator to hit a 10/20/40/30 target distribution
          (AA / A / B / NR). Re-tunable via \texttt{recalibrate\_thresholds\_from\_scores()}
          when real loss data becomes available.
    \item \textbf{13-measure spec weights}: taken verbatim from the BRI Resilience
          Function Specification (Section 3, p.\ 3). Spec author noted these are
          ``first implementation, not final scientific calibration''.
    \item \textbf{Regime multipliers}: taken verbatim from the spec (Section 4, p.\ 9).
          Reflect expected per-measure leverage under pluvial vs.\ fluvial vs.\
          coastal conditions.
    \item \textbf{Soft caps}: taken verbatim from the spec (Section 5, p.\ 9). Cap
          values 40, 60, 55, 65 are domain-engineer judgment calls.
    \item \textbf{Damage modifier $\alpha$}: pluvial 0.65, fluvial 0.60, coastal 0.50,
          per spec recommended starting values.
\end{itemize}

\subsection{Mapping Spec Measures to CDM Fields}
The model reads inputs from existing CDM fields per the binding table below. Nine
measures map directly to dedicated fields; four use proxy fields (flagged with
$\dagger$) because the CDM lacks a dedicated equivalent.

\begin{center}
\small
\begin{tabular}{p{4.5cm}p{7cm}c}
    \toprule
    \textbf{Spec Measure (weight)} & \textbf{CDM Source} & \textbf{Proxy?} \\
    \midrule
    \texttt{lowest\_occupied\_floor\_elevation} (20) & \texttt{Construction.FloorLevelMeters} (continuous, elev.\ table) & \\
    \texttt{critical\_systems\_elevation} (15) & \texttt{FloodProtection.ElectricalSystemsAboveFlood} (5-level) & \\
    \texttt{site\_drainage\_topography} (10) & \texttt{SiteAndDrainage.OverlandFlowPathsMaintained} (5-level) & \\
    \texttt{onsite\_retainage\_capacity} (10) & \texttt{SiteAndDrainage.OnsiteDrainageSizedForDesignStorm} (5-level) & \\
    \texttt{permeable\_surface\_share} (6) & \texttt{SiteAndDrainage.PermeableOrRetentionMeasures} (5-level) & \\
    \texttt{backflow\_protection} (6) & \texttt{FloodProtection.BackflowPreventionInstalled} (5-level) & \\
    \texttt{lower\_level\_flood\_compatible\_design} (8) & \texttt{SiteAndDrainage.BasementFloodStrategy} (own enum) & \\
    \texttt{water\_resistant\_materials} (8) & \texttt{FloodProtection.PermanentFloodProofingAtEntries} (5-level) & $\dagger$ \\
    \texttt{debris\_impact\_resistance} (5) & \texttt{BuildingAssessment.OpeningsWindResistant} (5-level) & $\dagger$ \\

% 5. IMPLEMENTATION DETAILS

\mkmimplementation

\subsection{Module Layout}
All resilience logic lives in a single file:
\texttt{src/port/rand/thames/property/property\_random/resilience.py}. The file is
organised in six clearly-labelled sections:

\begin{enumerate}[nosep]
    \item BRI letter-rating constants (Sections~1 and 2 of the file)
    \item BRI letter-rating functions
    \item Resilience generator constants (age/condition/zone priors)
    \item Resilience generator functions
    \item Flood-spec model constants (13 weights, regime multipliers, compliance maps)
    \item Flood-spec model functions
\end{enumerate}

\noindent Co-locating the constants with the functions that use them keeps the
calibration story in one place.

\subsection{Helper Module}
\texttt{src/port/cdm/property/bri.py} provides \texttt{apply\_bri\_rating()} which
reads the resilience checklist from a property record and writes the letter rating
fields. The flood-spec model is applied by
\texttt{apply\_flood\_resilience\_score()} in the same \texttt{resilience.py} file.

\subsection{Builder Integration}
\texttt{port.src.property.main.builder.BuilderMixin.\_populate\_resilience\_and\_rating}
runs three steps after the schema-walker has built the rest of the property record:
(1) \texttt{generate\_resilience} builds the checklist sub-sections;
(2) \texttt{apply\_bri\_rating} stamps the per-hazard + overall letter ratings;
(3) \texttt{apply\_flood\_resilience\_score} fills the BRI score fields.

\subsection{Determinism}
Per-property non-flood hazard scores (BRIWindScore, BRIFireScore, BRISeismicScore)
are jittered copies of BRIFloodScore $\pm 0.05$. The jitter RNG is keyed by
\texttt{PropertyID} so that two evaluations of the same property produce identical
outputs.

The model is validated through three layers of tests under \texttt{tests/port/cdm/}.

\subsection{Test Suite Layout}
\begin{itemize}[nosep]
    \item \texttt{test\_bri\_helper.py} (8 tests) --- \texttt{apply\_bri\_rating}
          writes the correct fields, leaves score fields blank where appropriate,
          handles missing \texttt{HazardProfile}.
    \item \texttt{test\_bri\_aggregation.py} (34 tests) --- letter-rating math:
          \texttt{\_field\_credit} for booleans and enums, \texttt{score\_section},
          \texttt{score\_hazard}, weakest-link logic, ``+'' modifier, calibration helpers.
    \item \texttt{test\_resilience\_generator.py} (21 tests) --- generator behaviour:
          level mapping, age-bias correctness, condition multiplier, flood-zone uplift,
          BasementFloodStrategy invariants, distribution sanity check.
    \item \texttt{test\_consistency\_fixes.py} (37 tests) --- builder post-step
          consistency rules.
    \item \texttt{test\_schema\_invariants.py} (30 tests) --- structural invariants
          on \texttt{PROPERTY\_SCHEMA}.
    \item \texttt{test\_flood\_resilience\_model.py} (68 tests) --- new flood-spec
          model: constants, elevation banding, compliance for all 13 measures, soft
          caps, regime mapping, damage modifier $\alpha$ boundaries, write-back
          semantics.
\end{itemize}

\subsection{Sanity Checks}
Beyond unit tests, the module exposes \texttt{sanity\_check\_distribution()} which
generates a synthetic Thames property population and reports the actual vs.\ target
rating distribution. The Thames target is 10/20/40/30 (AA/A/B/NR).

% 8. MODEL LIMITATIONS AND KNOWN WEAKNESSES
% ===================================================================
\mkmlimitations

The model is structurally faithful to its design intent but is calibrated for
\emph{indicative} rather than \emph{actuarially accurate} use. Several limitations
are inherited from the spec author's own caveats.

\subsection{Known Limitations}

\begin{description}[nosep]
    \item[BRI-L1: Distribution shape.] The current flood resilience score
          distribution is bell-centred (mean $\approx 58$, median $\approx 57$) rather
          than the design-target right-skewed shape with a heavy left tail of
          low-quality stock. Generator priors will need re-tuning.

    \item[BRI-L2: No location/hazard context normalisation.] A Zone 1 property and a
          Zone 3b property with identical resilience measures currently receive
          identical scores. The IFC BRI methodology supports context-normalisation
          (high-hazard sites need more measures for the same rating), but it is not
          yet implemented. \emph{Design under review.}

    \item[BRI-L3: Damage modifier not integrated.] $M(S, r)$ is computed and returned
          by \texttt{apply\_flood\_resilience\_score} but is not yet wired into the
          existing depth-damage flood loss estimator. Phase 2.

    \item[BRI-L4: Four proxy mappings (BRI-A7).]
          \texttt{water\_resistant\_materials},
          \texttt{debris\_impact\_resistance},
          \texttt{roof\_drainage\_standard}, and
          \texttt{roof\_membrane\_openings\_seal} use proxy CDM fields. Aggregate
          weight at risk: 20 of 100 spec points.

    \item[BRI-L5: Thames-specific calibration.] Weights and thresholds do not
          generalise to other catchments without re-tuning. Per-catchment copies of
          \texttt{resilience.py} required when other catchments are onboarded.

    \item[BRI-L6: Confidence score not implemented.] The spec defines a separate
          confidence indicator combining verification, evidence quality, recency, and
          field completeness. Not yet implemented.
\end{description}

\subsection{Known Failure Modes}
\begin{itemize}[nosep]
    \item All-Verified resilience checklist produces score near 100 --- unrealistic if
          no real-world property scores that high. Soft caps mitigate but do not
          eliminate.
    \item Properties with \texttt{HazardClass = None} across all hazards produce
          overall rating from the fallback weighted-score path, which differs subtly
          from the weakest-link path used when at least one hazard is applicable.
    \item \texttt{FloorLevelMeters} at or below 0 triggers the
          \texttt{lowest\_occupied\_floor\_elevation} soft cap at 40 --- correct
          behaviour but coarse.
    \item Regime multipliers and soft caps interact non-trivially: a pluvial-regime
          property with both retainage and drainage at compliance $= 0$ is capped at
          55 regardless of other strengths.
    \item PropertyID-keyed jitter RNG for non-flood hazard scores means two
          properties with the same flood score receive different sibling scores,
          which is intentional but can surprise consumers expecting hash-stability.
\end{itemize}
